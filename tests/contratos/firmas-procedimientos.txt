# El 2026-09-11 se agrego un parametro a p_registrar_sesion. La aridad paso de

# carpetas, descubiertos al dia siguiente, y en una de las suites ni siquiera
# se vieron porque el runner se caia antes de imprimir.
#
# Con este archivo, ese cambio no puede entrar sin que alguien edite estas
# lineas. Y el momento de editarlas es exactamente el momento de acordarse de
# ir a buscar los llamadores.
#
# ESTE ARCHIVO NO BUSCA LLAMADORES y el test tampoco. Ninguno de los dos sabe
# si los CALL estan al dia. Lo unico que garantizan es que la firma no cambie
# de callado. El relevamiento de la version que si los busca -- y de las tres
# formas que tiene de dar verde falso -- esta en AUDITORIA.md (2026-09-12).
#
# ----------------------------------------------------------------------
# COMO SE ACTUALIZA
#
# Cuando cambies una firma en schema.sql, el test va a fallar y el mensaje del
# rojo trae LA LINEA EXACTA para pegar aca. No hay que escribirla a mano ni
# contar parametros: la dicta el mismo parser que despues la verifica.
#
# FORMATO:  nombre | aridad | IN/OUT nombre_parametro, IN/OUT nombre, ...
#
# La aridad cuenta TODOS los parametros, IN y OUT juntos, porque eso es lo que
# cuenta MySQL en un CALL. `p_mensaje` es un argumento mas.
#
# La firma esta ademas de la aridad por un motivo medido: p_registrar_sesion y
# p_registrar_sesion_race_test tienen los DOS aridad 10, y son procedimientos
# distintos. Contar no alcanza. Dar vuelta dos parametros del mismo tipo no
# cambia la aridad, MySQL no se queja, y el dato entra en la columna
# equivocada: ese caso solo lo agarra la lista de nombres.
#
# ----------------------------------------------------------------------
# QUE NO ESTA ACA, Y POR QUE
#
#   p_generar_demo()                -- vive en seed_demo.sql, no en schema.sql.
#                                      Es un generador de datos de demo, sin

#                                      Es un fixture con firma propia, a
#                                      proposito distinta de la real; no es
#                                      parte del schema y no lo llama nadie mas.
#
# Los dos quedan afuera porque este test sujeta el CONTRATO DEL SCHEMA. Si

# ----------------------------------------------------------------------
